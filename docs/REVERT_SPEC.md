# Spec: Revert from here, /undo, /redo, Timeline revert, RevertConfirmDialog

Source: @oracle design (2026-10-10). Decision-complete; implement as written.

## 0. File restore = private git snapshot (opencode port)
Files are restored from a private git snapshot store, not from the CLI (`enableFileCheckpointing` / `rewindFiles` were removed: they only tracked main-thread Write/Edit/NotebookEdit, not Bash or subagent edits, and the UI reported "No file changes to restore" as success). Ported from opencode `snapshot/index.ts` + `session/revert.ts`. Code: `claude/snapshot.ts` (git plumbing, no vscode imports), `claude/fileHistory.ts` (per-session checkpoint log), `claude/revertStore.ts` (markers only).
- Private git dir `<storageDir>/snapshot/<sha1(realpath(toplevel)).slice(0,16)>`, objects borrowed from the user's repo through `objects/info/alternates`; the user's index, refs and config are never touched. `info/attributes` = `* -text -filter -ident -working-tree-encoding` (byte-exact). The user's `info/exclude` is copied before every track.
- Every git call: `--git-dir/--work-tree`, `core.longpaths/symlinks/autocrlf=false/quotepath=false/fsmonitor=false`, all `GIT_*` env stripped, `GIT_TERMINAL_PROMPT=0`, `-z` output, pathspecs via stdin. Index/ref mutating calls run through one promise-chain lock per `GitSnapshot`. `git add` runs with `--ignore-errors` (an unreadable file or unborn nested repo is skipped with a warning instead of failing every snapshot; any other `fatal:` still fails). A corrupt private index ("index file corrupt/smaller than expected", bad signature) is deleted and rebuilt once; a stale `index.lock` (older than 10 min) reported by a failing `track` is removed and `track` retried once. `info/attributes`, alternates and config are rewritten on every open (repairs a half-finished init); lock files are only removed when older than 10 minutes. `restore` reads every tree before touching the disk.
- Setting `claudekei.fileSnapshots` (default true); Git path from VSCode `git.path`, else `git` on PATH.
- Checkpoint log per session: `<storageDir>/checkpoints/<sessionId>.json` (`{version:1, worktree, checkpoints:[{uuid, tree, files?}]}`, `files` undefined = open).
- `resumeSessionAt` facts below still apply to the conversation cut.

## 0c. Subagent context (rolled back at commit)
`resumeSessionAt` only cuts the main message list. Claude Code keeps each subagent in `<project>/<sid>/subagents/agent-<id>.jsonl` (+ `.meta.json`) and reloads the whole file when the agent is resumed with SendMessage, so reverted work would stay in the subagent's context. At **commit** (never at revert, so /redo keeps working) `ClaudeSession.commitRevert` rolls them back, after `closeProcess()` and before the next spawn (no race with the CLI or the plugin hooks). Code: `claude/subagentCut.ts` (pure, injectable fs), `claude/pluginStateCleanup.ts`.
- Attribution: only `user` entries carry `promptId` (the id of the main user turn they ran under; verified on real transcripts: main and subagent files, assistant/attachment/metadata entries have none). `revertedPromptIds(main, targetUuid)` = (`promptId`s of the target user entry and of every non-sidechain user entry after it) minus (those of every main user entry before it: a prompt queued during an earlier turn can be injected later under that turn's id, and that turn is kept), computed **once**, stored in the committed marker (`RevertMarker.promptIds`) before anything is rewritten. A reload (or failed cut) with a committed marker re-applies the cut before the next spawn (`pendingCut`); it is idempotent and, because the set is fixed, never matches turns of the new branch. A target without `promptId` (older CLI) yields an empty set: nothing is trimmed.
- Trim rule per `agent-*.jsonl`: a chain line (has `uuid`) is dropped when its own `promptId` is in the set, or, if it has none, when the nearest preceding line with a `promptId` in the same file is (assistant / attachment lines inherit their turn). Lines before any `promptId` and lines without `uuid` (metadata) are always kept; an unparsable line is kept unless it comes after a dropped line (then it is the truncated tail of a reverted turn and is dropped). Nothing to drop = nothing written. Otherwise tmp file + rename. A file left without chain lines is deleted together with its `.meta.json` and the agentId is recorded as removed.
- Parent chain: transcripts are append-only, so reverted lines are a suffix and the kept `parentUuid` chain stays valid. If they are not (interleaved turns), the kept lines are re-pointed to their nearest kept ancestor (`relinked` is logged).
- Failures (permissions, parse) are logged per file and never block the send; `pendingCut` retries before the next spawn. The first-message revert cuts before `deleteSession`.
- Plugin alias state (`~/.claude/plugins/data/<claudekei*>/sessions/<sid>.json`; the plugin is not modified): applied to **every** claudekei data directory that has a file for the session (the same set `pluginAliases.ts` reads). Protocol copied from the plugin's `store.mjs`: `<file>.lock` directory via mkdir (stale after 5 s, 3 s wait), read under the lock, write `<file>.<pid>.tmp` and rename. Children of deleted transcripts are removed (counters untouched: aliases are never reused); children of trimmed transcripts keep their alias but get `reads = []`, `status = 'idle'`, `lastUsedAt = createdAt`. Retry safety: the set of subagents the cut will rewrite (`trimmedAgentIds`) is computed by a dry run before the first rewrite and stored in the committed marker next to `promptIds`; every (re)application also reconciles under the lock: a child whose `agent-<agentId>.jsonl` is no longer in the subagents directory is dropped, so a cleanup interrupted after the files were deleted is completed by the retry. Reconcile only runs when the directory listing succeeds (an unreadable or missing directory removes nothing and is logged), so a missing directory is never read as "everything is gone"; the first-message revert trims before `deleteSession`, so the listing is still valid. A child whose transcript file is absent for any other reason is a dead alias anyway (SendMessage to it fails). Missing file, unrecognised schema (`version !== 1` / no `children` array), unreadable JSON or a lock not acquired in time are skipped with a warning; a lock directory is never created for a session the plugin does not know.
- Known limits: (M2) attachment entries of background agents (`queued_command`) carry no `promptId` and are under-cut; the extension starts the CLI with `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`, so the impact is low. (L4) A plugin soft mode / alias state set during a reverted turn (e.g. the mode itself) survives: only children are cleaned. (L5) A plugin hook that writes late (after the cut) can re-add an alias; the next commit's reconcile repairs it. (L6) SendMessage follow-ups that were never linked to a parent tool call (`fromMessageID` unset) stay visible in a kept child until a reload replays the trimmed transcript.
- One rule, two users: `ClaudeSession.revertedRange` (children created by the removed messages, plus each other child's messages from the first follow-up sent from a removed message) drives both the commit's removal events and the G1/G2 audit of edited files.
- UI at commit: `removalEvents` also emits `message.removed` for kept children's follow-up instructions whose `instruction.fromMessageID` is a removed main message, and for every message of that child after the first such instruction. After a reload `history.ts` replays the already trimmed transcripts (deleted children are skipped as before).

### 0d. Warnings for edits a revert cannot undo, and interrupt timeout
- Audit (preview and revert): `ClaudeSession.editedPaths` collects the paths of Write / Edit / MultiEdit / NotebookEdit tool parts in the reverted range: main messages from the target on, the child sessions created by their Agent calls, and, in the other children, what they did after the first follow-up sent from a reverted message (the range the commit removes). `FileHistory.audit` keeps the ones a snapshot can never hold (`GitSnapshot.unrestorable`): outside the repository, Git-ignored (`git check-ignore`), over the size limit, or inside a nested repository. The ignore check runs once (`git check-ignore --stdin -z`) against the private snapshot index, so a file that index tracks is never reported just because an ignore rule matches it now. They are appended to `filesError` as "N file(s) edited in these turns can't be restored: a, b, …" (first 5). Warning only: there is no pre-image hook. The audit only looks at Write / Edit / MultiEdit / NotebookEdit tool calls: Bash writes to Git-ignored or outside-the-repo paths are neither restored nor warned about (inside the repo, Bash changes are covered by the snapshots).
- `stopRunningTurn` waits at most 5 s for the CLI to acknowledge `interrupt()` (session timers), then closes the process anyway and logs a warning.

## 1. Decisions
- D1 Revert = mark + restore files now (git snapshots); truncate conversation on next send. Host sets `Session.revert = {messageID}`; UI filters. Next send commits: close process, respawn with `resume` + `resumeSessionAt: cutUuid` (same id), remove hidden messages from host state, drop the checkpoints from the target onward, clear marker.
- D2 Only main-session user messages with `claudeUuid`, no `instruction`. Never in `sub_` children; no assistant targets.
- D3 Cut uuid = last kept chain entry before target — reuse fork logic `ClaudeSessionManager.ts` ~749-753 + `forkUuidOf` (~932-941), extracted into a shared helper. No cut uuid (first message) ⇒ on commit: `deleteSession`, fresh spawn with `sessionId`.
- D4 No process is needed for file operations: preview and revert never spawn one. A busy turn (or running background subagents) is stopped first (`stopRunningTurn`: `interrupt()` + `closeProcess()`); an idle live process stays alive.
- D5 Redo = head tree: before restoring, revert records a tree of the current files (`head`, pinned as `refs/claudekei/<sid>/revert-head`, stored in the marker, returned even when restoring fails). Unrevert restores only the files the revert covered from the head tree (never a blanket checkout). Re-reverting first unreverts the old marker (back to head state), then reverts to the new target. **Unrevert fails closed**: if any file cannot be written back, `FileHistory.unrevert` throws (naming the files) and keeps `revert-head` pinned; `ClaudeSession.revert` / `unrevert` propagate the error and keep the old marker, so /redo can be retried. The only conversation-only exceptions are "nothing to restore from" results (`{skipped}`: expired head, no checkpoint for the marker, store unavailable/turned off), which are logged as warnings and clear the marker. Markers without `head` (older versions) unrevert the conversation only. Revert never overwrites or deletes a planned file whose current content the head snapshot does not hold (over the size limit, Git-ignored, or skipped by track): it is left unchanged and listed in `filesError` ("N file(s) were left unchanged because they are Git-ignored or over the size limit: …"). The protected list is persisted in the checkpoint log (`protected`) at revert time and excluded again by `unrevert` (so /redo never overwrites or deletes them either); it is cleared by a successful unrevert and by `drop`. `preview` applies the same rule: protected files are neither listed nor counted and are reported in `filesError`. Files whose parent directory became a symlink are never written (reported as not restorable). If the store is only temporarily unavailable (git missing, setting off) while an old marker with a head must be unreverted, a second revert is refused ("Cannot move the revert while file snapshots are unavailable…") so the redo head is never dropped; `unrevert` itself still restores the conversation only.
- D6 Storage: marker `{uuid, resumeAt, head?}` in workspaceState key `claudekei.revertMarkers`. Snapshot store and checkpoint logs as in section 0. Every checkpoint tree is pinned (`refs/claudekei/<sid>/<uuid>`) because `gc --prune` is by object age; `gc --quiet --prune=7.days` runs at most once per 24 h; logs untouched for 30 days (and their refs) are swept at startup. Refs are deleted exactly (`drop`: the dropped checkpoints + `revert-head` in one `update-ref --stdin`; `remove`: by `<sid>/` component prefix). A commit failing to drop is logged and never blocks the send. The obsolete `<storageDir>/revert` directory is deleted once at startup.
- D7 Unavailable reasons (conversation-only revert, reason in `filesError`, dialog warns, /undo toasts): "Git was not found", "Git 2.26 or newer is required", "the workspace is not a Git repository", "the Git repository is your home directory", "file snapshots are turned off (claudekei.fileSnapshots)", "no file snapshot was taken when this message was sent", "the file snapshots for this message have expired", "N file(s) could not be restored: a, b, …", "file snapshots are unavailable in this host". No `rewindFiles` fallback for non-git workspaces.
- D-S3 Checkpoints mark points in time: each user message gets `{uuid, tree}` taken right before it is pushed to the CLI (`send()` awaits `fileHistory.begin`, after the interrupted check; queued messages checkpoint at push time; cancelled queued messages keep theirs). Rule "open while busy, closed while idle": the idle-triggered `end()` closes the open checkpoint (live-idle and no running subagent task). Whenever the session goes busy again without a `send` (a queued message was dequeued, the CLI continued on its own) and no revert marker exists, `ClaudeSession` calls `FileHistory.reopen(sid)`: the last checkpoint, if closed and with no newer one open, gets its `files` cleared and its uuid is open again, so its file list is recomputed from its start tree at the next close (a normal send needs no reopen: `begin` already opened a newer checkpoint, and `reopen` is then a no-op). `reopen` is chained on the per-session promise, an `end()` issued while a reopen is queued is chained behind it, a revert closes the checkpoint for good and a drop forgets it. A queued prompt folded into the running turn (no turn of its own) is never reopened, so edits made after the final idle are not attributed to it. `end()` only closes the checkpoint that was open when it was called (tracked as `openUuid` per session; a checkpoint whose `begin` is still running is never closed by an earlier `end`). A checkpoint is closed (files changed since computed) when the session becomes idle with no running subagent task (end of `publish`), or at the next send, at a revert, or when the process ends (`runPump` finally). "Revert to X" puts every snapshotted file changed after X was sent back to its state when X was sent; untouched files stay untouched. After a window reload mid-turn the checkpoint stays open on disk and is closed lazily.
- D8 All revert ops run in `ClaudeSession.exclusive()` (serialized with send/close/idle-close). Send during revert waits then commits. No UI send guard, no OpenKei lock/cascade.
- D9 Subagents: before commit, children of reverted turns stay in sidebar (known limitation, fixed at commit by section 0c). On commit emit `session.deleted` for every `sub_` child owned by a removed message (transitively). History reload skips subagent transcripts whose owning tool_use isn't in the kept chain.
- D10 UX like OpenKei: reverted messages hidden, no banner. Reverted user message text replaces composer text (only if that session is current). /undo /redo no confirm; buttons + Timeline use RevertConfirmDialog.

## 5. Concurrency
All serialized by `exclusive`. Revert while busy interrupts+closes (pending permissions denied, running tools error via runPump finally). Preview never interrupts and spawns nothing. `FileHistory` additionally chains its operations per session. Reload: marker in workspaceState, resolved by uuid. trimSessions never evicts sessions with marker.

## 6. Edge cases
Covered: Claude, subagent and Bash edits (any file change between two snapshots). Not covered: Git-ignored files, files over 10 MB (excluded from snapshots), submodule/nested-repo contents (gitlinks), other workspace roots (only the toplevel of the session cwd), turns before this feature shipped or older than 30 days (conversation-only). Concurrent sessions in one workspace share file spans. An unavailable store is probed again after 60 s (and on every preview/revert/warm-up); a failing `env()` is never remembered; a log written for another worktree is ignored; paths returned by `FileHistory` use the cwd's form of the toplevel (symlinked workspaces). Non-git workspace, git missing/too old, repo at $HOME (also the no-folder case), setting off -> conversation-only with the reason in `filesError` (D7). Directories a deleted file leaves empty are removed up to (excluding) the worktree and never the workspace folder (cwd) or any ancestor of it (`ENOTEMPTY`/permission stops the walk; a directory still holding ignored files stays). Because git cannot track empty directories, this also removes pre-existing empty folders that lose their last file in a revert. Symlinks are restored as symlinks (`core.symlinks=true`).
No file changes → conversation-only works, dialog `filesNone`. Files edited outside Claude after the target are overwritten, /redo brings them back. First message → resumeAt null, delete + fresh spawn same id. Same target as marker → no-op. Moving back/forward → any target (the old marker is unreverted first). Revert pending then send → commits last marker only. Marker uuid missing after reload → dropped with warning. Terminal continuation after revert → truncated too (known limitation). Queued-not-processed target → conversation-only.
